# エッセイ・ポートフォリオ 要件定義書

Oct 17, 2026 · @聖奈

## 1. 概要

エッセイを公開するポートフォリオを、**編集サイト**と**ポートフォリオサイト**の2つに分けて作る。URLを渡すだけで誰でも登録でき、ユーザーごとに自分専用のポートフォリオを持てる。他人のデータは編集できない。

### 目的

- 自分のエッセイと人となりを、生き生きとしたデザインで見てもらう
- URLを渡すだけで、知人も同じ仕組みで自分のポートフォリオを作れる
- 運営者（自分）はユーザーが増えても登録ごとの作業をしない

### 決定事項

| 項目 | 決定内容 |
| --- | --- |
| サイト構成 | 1リポジトリ（モノレポ）に2つのNext.jsアプリ。別URLで公開 |
| 利用者 | 誰でもセルフ登録。1ユーザーにつき1ポートフォリオ |
| 公開サイトの権限 | 閲覧専用。編集・ログイン機能は一切持たない |
| DB・認証 | Firebase（Authentication＋Firestore、無料のSparkプラン） |
| 画像保存 | Cloudinary（無料プラン）。Firebase Storageは使わない |
| テーマ選択 | プリセットから選択＋メインカラーの微調整 |
| エッセイ詳細 | 題名クリックで個別ページ（固有URL）に移動 |
| UI開発 | git worktreeでUI開発用の作業ブランチを切って進める |
| 開発ツール | Cursor＋Claude Code |

### 前提（仮置き・変更可）

- 利用者は数人〜数十人規模（無料枠内で運用）
- 対応言語は英語と日本語
- PC・スマホ両対応（スマホではカーソル演出の代わりにタップ・スクロール演出）

## 2. システム構成

2つのアプリは同じFirebaseプロジェクトを共有する。書き込めるのはログインした本人の編集サイトだけで、ポートフォリオサイトは公開済みデータを読むだけにする。画像はCloudinaryに置き、URLをFirestoreに保存する。

### 技術スタック

| 区分 | 採用技術 | 備考 |
| --- | --- | --- |
| モノレポ管理 | pnpm workspaces＋Turborepo | 2アプリと共通パッケージを1リポジトリで管理 |
| フレームワーク | Next.js（App Router）＋TypeScript | 両アプリ共通 |
| スタイル | Tailwind CSS＋CSS変数 | テーマ切替はCSS変数で実現 |
| アニメーション | Framer Motion | カーソル追従・スクロール演出 |
| リッチテキスト | Tiptap | 太字・斜体・文字サイズのツールバー |
| 認証 | Firebase Authentication | メール/パスワード＋Googleログイン |
| DB | Cloud Firestore | セキュリティルールで本人以外の書き込みを拒否 |
| サーバー側検証 | firebase-admin | 編集サイトのAPIでのみ使用（ユーザーのトークン確認） |
| 画像 | Cloudinary | カード登録不要の無料プラン。正方形トリミング・サイズ最適化をURL指定で自動処理 |
| 多言語 | next-intl | 画面の文言を英語・日本語で切替 |
| ホスティング | Vercel（プロジェクトを2つ作成） | Root Directoryをそれぞれ apps/editor、apps/portfolio に設定 |

### ディレクトリ構成

```
my-portfolio/
├─ apps/
│  ├─ editor/      編集サイト（ログイン必須）
│  └─ portfolio/   ポートフォリオサイト（閲覧専用）
├─ packages/
│  ├─ shared/      型定義・テーマプリセット定義・翻訳ファイル
│  └─ ui/          エッセイ本文の表示部品など共通UI
├─ firebase/
│  ├─ firestore.rules         セキュリティルール
│  └─ firestore.indexes.json  インデックス定義
├─ turbo.json
└─ pnpm-workspace.yaml
```

### URL（例）

- 編集サイト：`editor-<サイト名>.vercel.app`（利用者に渡すURL。検索エンジンには載せない）
- ポートフォリオ：`<サイト名>.vercel.app/<ユーザー名>`（各利用者が人に見せるURL）

## 3. 編集サイトの機能要件

利用者が自分で登録・ログインし、自分のプロフィール・テーマ・エッセイだけを編集する管理画面。運営者が登録ごとに作業することはない。

### 画面一覧

| 画面 | パス | 内容 |
| --- | --- | --- |
| 新規登録 | /signup | メール＋パスワード、またはGoogleで登録。メール確認必須 |
| ログイン | /login | メール＋パスワード、Google。パスワード再設定メール送信 |
| 初回設定 | /onboarding | ユーザー名（ポートフォリオURLになる）を決める |
| ダッシュボード | / | 自分のエッセイ一覧（下書き・公開の状態つき）、自分のポートフォリオURLとコピーボタン |
| プロフィール編集 | /profile | 顔写真、名前、ひとことコメント |
| テーマ設定 | /theme | プリセット選択、メインカラー微調整、プレビュー |
| エッセイ新規・編集 | /essays/new、/essays/\[id\] | 題名、本文エディタ、公開設定 |
| アカウント設定 | /settings | 表示言語、パスワード変更、退会（全データ削除） |

### 登録・初回設定

- 登録後、確認メールのリンクを押すまで編集不可
- ユーザー名は半角英小文字・数字・ハイフンで3〜20文字。重複不可
- `admin` `login` `signup` `essays` などの予約語は使用不可
- 初回設定の完了時に、プロフィールとテーマの初期データを自動作成

### プロフィール編集

- 顔写真をアップロード（JPEG/PNG/WebP、5MBまで）。Cloudinaryに保存し、正方形トリミングして表示
- 名前（30文字まで）、ひとことコメント（100文字まで）を入力
- 保存すると自分のポートフォリオのトップに反映

### エッセイ編集

- 題名（必須、60文字まで）と本文を入力
- ツールバーのボタンで書式を選択：太字、斜体、文字サイズ（小・標準・大・特大）、見出し、引用、区切り線
- 本文はTiptapのJSON形式で保存（HTMLを直接保存しない）
- 状態は「下書き」「公開」の2種類。公開にしたものだけがポートフォリオサイトに出る
- 公開日を表示用に保持。一覧の並び順は公開日の新しい順（ドラッグでの並べ替えは今後検討）
- 自動保存（入力停止から数秒後）と、離脱時の未保存警告
- 削除は確認ダイアログを挟む

### テーマ設定

- プリセットをカードで並べ、選ぶとプレビューに即時反映
- メインカラーをカラーピッカーで微調整（「プリセットに戻す」ボタンあり）
- 保存した時点でポートフォリオサイトに反映（詳細は「5. テーマ仕様」）

## 4. ポートフォリオサイトの機能要件

訪問者が見るだけのサイト。ユーザーごとのURLでその人のポートフォリオを表示し、トップで人となりを伝え、スクロールでエッセイの題名に出会う構成にする。

### 画面一覧

| 画面 | パス | 内容 |
| --- | --- | --- |
| サイトトップ | / | サービス紹介と編集サイトへの登録リンク（個人の一覧は出さない） |
| 個人トップ | /\[ユーザー名\] | ヒーロー（名前・顔写真・コメント）→ スクロールでエッセイ題名一覧 |
| エッセイ詳細 | /\[ユーザー名\]/essays/\[slug\] | 題名、公開日、本文。前後のエッセイ・個人トップへ戻る導線 |
| 404 | — | 存在しないユーザー・非公開エッセイもここ。テーマに合わせたデザイン |

- 各ページは、そのユーザーが選んだテーマで表示する

### トップページ

1. ファーストビューに名前・顔写真・ひとことコメントを大きく表示（読み込み時に文字や写真がふわっと登場）
2. スクロールを促すインジケーター
3. スクロールするとエッセイの題名が順番に浮かび上がるように並ぶ（公開日の新しい順）
4. 題名をクリックすると個別ページへ遷移（ページ切り替えアニメーションあり）

### 動き・演出

- マグネティックボタン：カーソルが近づくとボタンや題名がカーソル方向へ少し引き寄せられ、離れると戻る
- カスタムカーソル：テーマ色の丸いカーソルが追従し、リンク上で拡大する
- スクロール連動：題名のフェードイン・スライドイン、背景の色や図形がゆっくり動く
- スマホ：カーソル演出はオフにし、タップ時の反応とスクロール演出で代替
- OSの「視差効果を減らす」設定がオンの人には動きを控えめにする

### 閲覧専用であること

- ログイン画面・編集画面・書き込み処理を一切持たない（詳細は「7. セキュリティ要件」）

### 反映タイミング

- 編集サイトで保存・公開すると、ポートフォリオサイトに数秒〜1分程度で反映（Next.jsのキャッシュ再検証を使用）

## 5. テーマ（色味・テイスト）仕様

テーマは「プリセット1つ＋メインカラー1色」の組み合わせで決まり、CSS変数として両アプリに適用する。

### プリセット案（初期4種・名称や中身は変更可）

| プリセット | 雰囲気 | フォント | 動きの強さ |
| --- | --- | --- | --- |
| ポップ | 明るい色、丸みのある図形 | 丸ゴシック系 | 大きめ・弾む |
| ナチュラル | 生成り・くすみカラー、手書き風の線 | 明朝＋ゴシック | ゆったり |
| モノトーン | 白黒＋差し色1色、余白多め | 明朝系 | 控えめ・上品 |
| ナイト | 暗い背景、光るアクセント | ゴシック系 | なめらか・発光 |

### プリセットが持つ値

- 背景色、文字色、サブ文字色、アクセント色（メインカラー）
- 見出し・本文のフォント
- 角丸の大きさ、背景の装飾パターン
- アニメーションの強さ（引き寄せ距離・速度）

### 微調整

- 変更できるのはメインカラーのみ。ボタン・カーソル・リンク色に反映
- 背景色との文字コントラストが低すぎる場合は警告を表示
- プリセット定義は packages/shared に置き、両アプリで同じ定義を使う

## 6. データ設計（Firestore・Cloudinary）

Firestoreは3つのコレクションで、ユーザーごとにデータを分けて持つ。画像はCloudinaryに保存し、URLだけをFirestoreに入れる。

### users/{uid}（1ユーザー1ドキュメント）

| フィールド | 型 | 内容 |
| --- | --- | --- |
| username | string | ポートフォリオURLに使うユーザー名 |
| name | string | 名前 |
| comment | string | ひとことコメント |
| avatarUrl | string | Cloudinary上の顔写真URL |
| theme.preset | string | pop / natural / mono / night |
| theme.accentColor | string または null | メインカラー（#RRGGBB）。null ならプリセットの既定色 |
| locale | string | ja / en（表示言語） |
| createdAt / updatedAt | timestamp | 作成・更新日時 |

### usernames/{username}（重複防止用）

| フィールド | 型 | 内容 |
| --- | --- | --- |
| uid | string | このユーザー名を持つユーザーのID |

- 初回設定でusersとusernamesを同じトランザクションで作成し、同じユーザー名の二重登録を防ぐ
- ポートフォリオはユーザー名からuidを引いてデータを読む

### users/{uid}/essays/{essayId}

| フィールド | 型 | 内容 |
| --- | --- | --- |
| title | string | 題名 |
| slug | string | URL用の文字列（ユーザー内で一意、自動生成） |
| body | map | 本文（Tiptap JSON） |
| status | string | draft / published |
| publishedAt | timestamp | 公開日 |
| createdAt / updatedAt | timestamp | 作成・更新日時 |

- インデックス：status＋publishedAt（新しい順）

### Cloudinary

- 保存先フォルダ：`avatars/{uid}/`。1人1枚で、新しい写真は上書き
- アップロードは「署名付きアップロード」：編集サイトのAPIがログイン中のユーザーを確認してから署名を発行し、保存先を本人のフォルダに固定する
- 表示はURLで正方形トリミング・WebP変換・サイズ縮小を指定する

## 7. セキュリティ要件

他人のデータを編集できない状態と、ポートフォリオサイトから編集できない状態を、コード・キー・DBルールの3層で担保する。Firestoreのセキュリティルールで拒否するので、どのアプリのコードを改造されても他人のデータには書き込めない。

| 層 | ポートフォリオサイト | 編集サイト |
| --- | --- | --- |
| コード | 読み取り処理のみ。ログイン・編集画面・書き込み処理を含めない | ログイン＋メール確認必須。未ログインは /login へ |
| キー | Firebaseの公開設定のみ。firebase-admin・Cloudinaryの秘密鍵は置かない | firebase-admin・Cloudinaryの秘密鍵はサーバー側（API）だけで使用 |
| DBルール | 未ログインは「プロフィール・ユーザー名・公開済みエッセイ」の閲覧のみ | 自分のuidのドキュメントだけ作成・更新・削除可 |

### Firestoreセキュリティルール

- users/{uid}：読み取りは誰でも可。書き込みは `request.auth.uid == uid` かつメール確認済みのときのみ
- usernames/{username}：読み取りは誰でも可。作成は「未使用の名前」かつ「自分のuid」のときのみ。更新は禁止、削除は持ち主のみ
- essays：読み取りは `status == 'published'` か持ち主のみ。書き込みは持ち主のみ
- 文字数上限・statusの値などもルールでチェックする
- ルールはFirebase Emulatorでテストしてからデプロイする

### 荒らし・乱用対策

- 1ユーザーあたりエッセイ200件、本文は1件あたりFirestoreの上限（1MB）より十分小さい範囲に制限
- 画像は1人1枚・5MBまで（Cloudinaryの署名で制限）
- 不正ユーザーはFirebaseコンソールからアカウント無効化

### その他

- 編集サイトは `noindex` を設定し、検索結果に出さない
- 本文はTiptap JSONから描画し、生のHTMLを埋め込まない（スクリプト混入対策）
- Firebaseの「承認済みドメイン」にVercelのURLを登録する
- 秘密鍵などの環境変数は各Vercelプロジェクトにのみ設定し、リポジトリにコミットしない

## 8. 非機能要件

| 項目 | 要件 |
| --- | --- |
| 表示速度 | ポートフォリオの個人トップはLighthouseのPerformance 90以上を目標。画像はCloudinaryで最適化 |
| 対応端末 | PC（Chrome・Safari・Edge最新版）、スマホ（iOS Safari・Android Chrome） |
| レスポンシブ | 幅375pxのスマホから大画面まで崩れない |
| 多言語 | 画面の文言は英語・日本語を切替。エッセイ本文は書いた言語のまま表示 |
| アクセシビリティ | 文字と背景のコントラスト確保、キーボード操作可、動きを減らす設定に対応 |
| SEO・共有 | 各エッセイにタイトル・説明・OGP画像（題名入り）を設定 |
| 費用 | Vercel Hobby・Firebase Spark・Cloudinary Freeの無料枠内で運用。クレジットカード登録なし |
| 運営者の作業 | 初期設定のみ。ユーザー登録・ログイン・パスワード再設定・退会は利用者が自分で完結 |

## 9. 開発の進め方

土台（DB・編集サイト）をmainで作り、ポートフォリオのUIデザインはworktreeで切った作業ブランチで進めてからmainに統合する。

### ブランチ・worktree運用

- `main`：常に動く状態を保つ。Vercelの本番デプロイ元
- `feature/portfolio-ui`：ポートフォリオのUIデザイン用。worktreeで別フォルダに展開し、Cursorで別ウィンドウとして開く

```
# mainのフォルダで実行
git worktree add ../my-portfolio-ui -b feature/portfolio-ui
# 作業後
git worktree remove ../my-portfolio-ui
```

- UIブランチでもVercelのプレビューURLで見た目を確認し、問題なければプルリクエストでmainへマージ

### フェーズ

1. セットアップ：モノレポ作成、Firebaseプロジェクト作成（Authでメール/Googleを有効化、Firestore作成）、Cloudinaryアカウント作成、セキュリティルール作成とEmulatorでのテスト
2. 編集サイト：新規登録・ログイン・初回設定、プロフィール編集（画像アップロード）、エッセイエディタ、テーマ設定、アカウント設定
3. ポートフォリオ（最小）：/\[ユーザー名\] でデータを表示するだけの簡素な画面で連動を確認
4. ポートフォリオUI（worktreeブランチ）：ヒーロー、題名一覧、マグネティックボタン、カーソル、スクロール演出、テーマ反映
5. 仕上げ：多言語化、スマホ対応、アクセシビリティ、OGP、Vercelに2プロジェクトでデプロイし承認済みドメインを登録
6. 公開前テスト：別のGoogleアカウントで2人分登録し、互いのデータを編集できないことを確認

### Claude Codeへの指示のコツ

- 最初にこの要件定義書をリポジトリの `docs/requirements.md` に置き、`CLAUDE.md` から参照させる
- `CLAUDE.md` に「apps/portfolio には書き込み処理・firebase-admin・秘密鍵を絶対に追加しない」と明記する
- セキュリティルールは「他人のデータに書き込めないこと」のテストも一緒に書かせる
- 1フェーズずつ依頼し、終わるごとに動作確認とコミットをする
